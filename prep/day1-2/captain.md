# Капитан · Дни 1–2: договорённости

10.10.2026 · по «Плану подготовки команды к хакатону»

## 1. Протокол кикоф-созвона (60 мин, все 5)

**Формат.** Хакатон 2 дня, одна задача прогнозирования, «голые» машины, приватные GitLab и облако. Цель недели: шаблон `forecast-template`, который поднимается одной командой (`make setup && make up`). Цель хакатона: к концу дня 1 в облаке работает полная версия на бейзлайне.

**Роли подтверждены по таблице плана.** Капитан: приоритеты, тайминг, презентация, приём результата. Код пишет только при закрытых своих задачах. ML: пайплайн и FastAPI `/predict`, `/health`. C#: публичный API, PostgreSQL, клиент к ML. Фронт: дашборд. DevOps: окружение, CI/CD, деплой, офлайн-запас пакетов.

**Решения:**
- Фронт: React + TypeScript + Vite, MUI, графики на **ECharts**: доверительный интервал и много рядов в нём делаются проще, чем в Recharts.
- Архитектура: фронт → C# API → ML-сервис. ML наружу не торчит.
- Канал: один общий чат и тред «Решения», куда капитан пишет каждое принятое решение одной строкой.
- Контракты OpenAPI (фронт ↔ API, API ↔ ML) готовы к концу дня 3. Владельцы: C# и ML, фронт ревьюит.
- Сквозной прогон «пустышки» к концу дня 4. Репетиция на Store Sales в дни 5–6.
- Ежедневный стендап в 10:00 на 15 минут: сделал, делаю, блокеры.

**Действия:** DevOps создаёт репозиторий и защищает `main` (сегодня). Капитан отправляет вопросы организаторам (сегодня). ML скачивает данные Kaggle и раскладывает в `data/store-sales/` (день 2). Капитан и ML смотрят прошлые хакатоны организаторов (день 2).

## 3. Git-договорённости

- **Ветки:** `main` защищена, в неё никто не пушит напрямую. Рабочие ветки называются `<зона>/<кратко>`, например `ml/lgbm-baseline`, `api/upload-csv`, `infra/ci-dotnet`. Ветка живёт не дольше одного дня.
- **MR:** маленький, одна задача, CI зелёный. Нужен 1 ревьюер, и он не автор. Если меняется контракт OpenAPI, ревью обязательно от обеих сторон стыка.
- **Кто мержит в `main`:** автор после аппрува и зелёного CI, способ слияния squash. Капитан мержит контракты и всё, что меняет `docker-compose` и `.gitlab-ci.yml`, вместе с DevOps.
- **Коммиты:** `<зона>: что сделано` в повелительном наклонении (`ml: добавить лаги 7/14/28`). Данные, модели и секреты не коммитим, `.gitignore` заводит DevOps в первый же день.
- **Код-фриз** (за 3–4 ч до сдачи, объявляет капитан): после него в `main` попадают только багфиксы с аппрувом капитана. Ставим тег `release-candidate`, DevOps делает финальный деплой с этого тега. После деплоя без капитана `main` не трогаем. Если прод упал, откатываемся на тег, а не чиним вперёд.

## 4. Постановка репетиции (объявление в первый час)

**Задача:** Store Sales (Corporación Favorita, Эквадор). Прогноз дневных продаж для 54 магазинов × 33 семейств = 1782 ряда. Бизнес-смысл: план закупок и запасов по магазинам.
**Горизонт:** 16 дней, 16.08–31.08.2017 (`test.csv`).
**Метрика:** RMSLE. Валидация: последние 16 дней train (31.07–15.08.2017), только разбиение по времени. Сравниваем с сезонным naive (значение неделю назад).
**Сдача:** (1) `submission.csv` (`id,sales`) отправлен на Kaggle, публичный скор записан. (2) Сервис в облаке: выбираешь магазин и семейство, видишь график «факт / прогноз на 16 дней» с интервалом. (3) Защита 5 минут по структуре из плана, с видео-страховкой.

| Час | Капитан | ML | C# | Фронт | DevOps |
|---|---|---|---|---|---|
| 0–1 | Постановка, задачи, таймер | Загрузка, EDA, бейзлайн-сабмит | Адаптация контракта под store × family | Адаптация экранов, моки | Чистая VM, `make setup`, CI |
| 1–2 | Контроль, лог потерь времени | LightGBM на лагах/окнах, валидация | Загрузка CSV в PostgreSQL | Селекторы, график | Деплой «пустышки» |
| 2–3 | **Контрольная точка:** сквозной сценарий на бейзлайне в облаке | Модель → `/predict` | Вызов ML, сохранение прогнозов | Реальные данные с API | Стабилизация |
| 3–4 | Слайды | Праздники, промо, нефть | Экспорт, health checks | Таблица, экспорт | Логи, мониторинг |
| 4–5 | **Код-фриз**, сабмит лучшей модели | Цифры для слайдов | Только багфиксы | Видео демо | Финальный деплой |
| 5–6 | Два прогона защиты, ретро: где потеряли время | — | — | — | Проверка прода |

Если время урезаем до 4 ч, сжимаются часы 3–4. Контрольная точка на 3-м часу не сдвигается.

## 5. Расхождения «план ↔ репетиция» и кому поручено

| Расхождение | Что делаем | Кто |
|---|---|---|
| В плане метрики MAE/RMSE/MAPE/SMAPE, на Kaggle RMSLE | Добавить RMSLE и обучение на `log1p(sales)`. Обработать нули: MAPE на этих данных ломается. | ML |
| В плане праздники РФ, в данных праздники Эквадора: национальные, региональные, локальные, перенесённые (`transferred`), `Bridge`, `Work Day`, `Additional` | Сделать модуль праздников с параметром «страна/источник» и учесть привязку локальных и региональных праздников к городу и штату магазина из `stores.csv` | ML |
| Контракт «один входной ряд → прогноз», а здесь 1782 ряда и одна глобальная модель | Контракт API ↔ ML: пакетный запрос с ключом ряда (`store_nbr`, `family`), прогноз считается батчем заранее, API отдаёт его из БД | C# + ML |
| Экзогенные признаки, известные в будущем (`onpromotion`), и внешние ряды (`oil` с пропусками, `transactions` только для train) | Контракт должен уметь принимать будущие экзогенные признаки. Нефть заполняем ffill. `transactions` в признаки на горизонт не берём, иначе утечка. | ML, ревью капитан |
| Особенности данных: зарплата 15-го и в последний день месяца, землетрясение 16.04.2016, закрытые магазины и семейства с нулями | Флаги payday и earthquake. Ряды, где одни нули, прогнозируем нулём. | ML |
| Фронт: интервал предсказания (у LightGBM его нет), выбор из 1782 рядов | Интервал через квантильную регрессию или по остаткам валидации, это решает ML. Фронту нужны селектор магазина и семейства и агрегат по магазину. | ML + Фронт |
| Объём данных: train около 3 млн строк, загрузка CSV через API | Bulk insert (COPY), лимиты на размер загрузки, данные не идут через фронт | C# |
| Данные Kaggle требуют аккаунта и принятия правил, на диске их нет | Kaggle API-токен в секретах, а не в репозитории. Данные лежат в `data/store-sales/` и попадают в `.gitignore`. Скачать до дня 5. | DevOps + ML |
| В плане горизонт выбирает пользователь, здесь он фиксирован (16 дней) | Горизонт сохраняется как параметр. На репетиции ограничиваем его 1–16 днями. | Фронт + C# |
