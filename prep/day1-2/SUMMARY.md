## Снятые расхождения

| # | Расхождение | Решение |
| --- | --- | --- |
| 1 | UI-кит: MUI у капитана, Ant Design у фронтенда | **Ant Design.** UI-кит выбирает владелец зоны, а аргумент про ограничения бесплатной таблицы MUI весомый |
| 2 | Прогноз: синхронный `GET /api/forecast` у фронта, а у бэка `POST /forecasts` → `202` + опрос | **Запуск асинхронный, чтение синхронное.** `POST /api/forecasts` → `202 {runId}`, опрос `GET /api/forecasts/{runId}` раз в 2 с. График читает `GET /api/forecasts/latest/series?store=&family=&horizon=`, где `all` — агрегат. Фронт почти не меняется, бэк не держит запрос открытым по 2 минуты |
| 3 | Имена и регистр полей: фронт и бэк `camelCase` + `lo/hi`, ML `snake_case` + `lower/upper` | **Каждый стык в своём стиле, перевод делает C#.** Фронт ↔ API: camelCase, `yhat/lo/hi`. API ↔ ML: snake_case, `yhat/lower/upper`. Даты `YYYY-MM-DD`, вместо NaN `null`, ошибки в формате ProblemDetails (RFC 7807) |
| 4 | Где история и что такое `dataset_ref` | **История в Postgres у C#.** ML читает её из read-only view под отдельным пользователем. `dataset_ref` = `datasetId`. Справочники (stores, holidays, oil) лежат на общем volume `/data` и доступны ML только на чтение |
| 5 | Интервал для агрегата «все магазины» | **В первый день агрегат без полосы** (`lo/hi = null`, фронт её не рисует). Во второй день ML считает интервал агрегата по остаткам агрегированного ряда |
| 6 | Уровень интервала | **80 % (p10/p90)**, эмпирические квантили остатков CV в лог-пространстве по шагу горизонта |
| 7 | Health: у фронта `/api/health`, у бэка `/health/live` и `/health/ready` | Бэк отдаёт оба эндпоинта, nginx проксирует `/api/health` → `/health/ready`. По `/api/health` работают авто-мок фронта и smoke-проверка CI |
| 8 | Загрузка 3 млн строк через nginx | `client_max_body_size 500m` + запасной путь импорта с серверного volume |

## Таймауты стыка C# ↔ ML

`/train` только асинхронный (`job_id`). На одну попытку `/predict` — 120 с, всего 300 с, 2 ретрая только на 5xx и сетевые ошибки, повтор безопасен по `runId`. ML отвечает 422 на ошибку валидации и 503, если модель не загружена. Метрики CV ML отдаёт в ответе, это цифры для слайда.

## Находка DevOps: риск подтвердился уже сейчас

Docker Hub с этой машины не ответил за 25 с, при этом PyPI, NuGet и npm доступны через HTTP-прокси. Значит, демону Docker прокси или зеркало нужно настраивать отдельно от shell. Это тот же риск, что и на хакатоне. **Действие для DevOps в днях 2–4:** настроить прокси для dockerd (`/etc/systemd/system/docker.service.d/http-proxy.conf`) или registry-mirror и выгрузить запас образов через `docker save`.

## Ответы организаторов (2026-10-11)

- Заготовленный шаблон и LLM — **можно**.
- Kubernetes не используем, только **docker compose на VM**, sudo на VM есть. План Б на kustomize снимаем.
- **GitLab Runner работает в Docker** и ходит на VM по ssh, ключ хранится в GitLab CI/CD Variables. Это совпадает с нашей схемой деплоя по умолчанию.

## Ещё не уточнено

1. Как runner собирает образы: есть ли Docker внутри runner'а (DinD или privileged-режим, проброшенный `docker.sock`). Если нет, образы собираем прямо на VM через `docker compose build` по ssh.
2. Есть ли Container Registry в GitLab. Если нет, образы не пушим, а собираем на VM.
3. Доступ с VM и runner'а к Docker Hub, MCR, PyPI, NuGet и npm: напрямую, через прокси или через зеркала. На нашей машине Docker Hub уже недоступен.
4. Ресурсы VM: CPU, RAM, диск. Есть ли GPU (рассчитываем, что нет).
5. Публичный адрес: IP или домен, нужен ли TLS, какие порты открыты.
6. Формат сдачи (ссылка на сервис, репозиторий, сабмит), длительность защиты, критерии жюри.
