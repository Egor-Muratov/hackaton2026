## Ход 1. Чистый клон → стек в Docker без сети

Чистой VM не было, поэтому она имитировалась так:
- свежий `git clone` в отдельный каталог;
- офлайн-запас подложен в `<клон>/forecast-template/offline` (путь по умолчанию, `OFFLINE_DIR` не задавался);

- в `.env`: `OFFLINE=1`, `BUILD_NETWORK=none`, `HTTP_PORT=8088`, случайные пароли.

## Стык C# ↔ Python на отказ

ML остановлен:
- `/api/health` → 200 `Degraded` (`ml: Unhealthy`) за 2 с;
- `POST /api/forecasts` → 202, через 25 с прогон переходит в `failed` с понятной ошибкой «ML недоступен».

ML поднят → `make smoke` снова OK без перезапуска API.

## Что нашла репетиция и что исправлено

1. **Healthcheck api никогда не проходил.** В образе `aspnet` нет `curl`, а он стал бы `unhealthy` через ~2 мин. В днях 2–4 этого не видели, потому что стек в Docker не поднимался. Поставить `curl` через `apt-get` нельзя: это ломает офлайн-сборку. Проверка переписана на `bash` + `/dev/tcp` (compose, README).
2. **`SHA256SUMS` всегда «не сходились».** `MANIFEST.txt` перезаписывался после подсчёта сумм. Манифест исключён из сумм. Сам запас был цел.
3. Несоответствие `OFFLINE_DIR` проявляется только в раскладке этого репозитория, где шаблон лежит в подкаталоге. В отдельном репозитории шаблона путь по умолчанию `<repo>/offline` работает, это проверено на клоне.
