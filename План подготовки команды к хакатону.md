# План подготовки команды к хакатону

Oct 10, 2026 · @Bradley

## Цель подготовки

За неделю собрать и прогнать «скелет» решения, который подходит под любую задачу прогнозирования. На хакатоне останется подставить данные и модель, а не настраивать инфраструктуру с нуля.

Основное время на хакатонах теряется на окружении, деплое и стыковке частей системы, а не на ML. Поэтому подготовка закрывает именно эти зоны.

**Вводные:** 2 дня, одна ML-задача на прогнозирование, «голые» компьютеры с интернетом, приватный GitLab и приватное облако. Нужно решить задачу, настроить окружение, задеплоить сервис и защитить результат на презентации.

## Команда и зоны ответственности

У каждого своя зона. Капитан держит приоритеты, время и презентацию и пишет код, только если всё остальное под контролем.

| Роль | Зона на хакатоне | Что подготовить за неделю |
| --- | --- | --- |
| Капитан | Постановка задачи, приоритеты, тайминг, презентация, приём результата | Шаблон презентации, архитектурная схема, чек-лист сдачи, тайминг, общий README |
| ML-специалист | EDA, признаки, модель, валидация, метрики; тонкий Python-сервис инференса | Универсальный пайплайн временных рядов: лаги, окна, календарь, праздники РФ; бейзлайны (naive, сезонный naive, скользящее среднее), LightGBM/CatBoost; валидация по времени; MAE, RMSE, MAPE/SMAPE; FastAPI с `/predict` и `/health` |
| C#-бэкенд | Основной API и бизнес-логика | ASP.NET Core API, EF Core + PostgreSQL, загрузка и валидация CSV, HTTP-клиент к ML-сервису (`HttpClientFactory` + Polly), фоновые задачи, Serilog, health checks, Dockerfile |
| Фронтенд | Дашборд | Загрузка данных, график «факт / прогноз» с доверительным интервалом, таблица, выбор горизонта, экспорт; клиент по OpenAPI. Стек: React + TypeScript, графики Recharts/ECharts, готовый UI-кит (MUI или Ant Design) |
| DevOps | Окружение, CI/CD, деплой | Скрипт подготовки «голой» машины, docker-compose на 5 контейнеров, `.gitlab-ci.yml` (.NET + Python), deploy в облако, nginx, зеркала и запас образов, логи/мониторинг |
|  |  |  |

## Архитектура решения

C#-бэкенд владеет публичным API и данными, ML-сервис на Python только считает прогноз. Так у каждого своя зона, а на защите решение выглядит как продукт.

&#91;embedded content: архитектура решения · 5 контейнеров в облаке\]

Схема в Mermaid: `forecast-template/docs/architecture.md`. Пять контейнеров: nginx (единственный вход), frontend, api, ml, db (PostgreSQL).

Фронт обращается только к C# API. ML-сервис скрыт за ним и подменяется без изменений во фронте. Экспорт модели в ONNX и запуск прямо в C# — бонус, если останется время: признаки пришлось бы дублировать на C#, и любое расхождение даст тихие ошибки.

## Подготовка по дням

К концу недели шаблон должен подниматься на чистой машине одной командой и пройти полную репетицию.

### Дни 1–2: договорённости

- [ ] Созвон на 1 час: формат, роли, этот план
- [ ] Изучить прошлые хакатоны организаторов: задачи, данные, критерии жюри
- [ ] Уточнить у организаторов: тип облака (VM / Kubernetes / OpenStack), GPU, GitLab Runner и Container Registry, доступ к Docker Hub, PyPI, NuGet, HuggingFace, формат сдачи, длительность защиты
- [ ] Завести общий канал; договориться о ветках, MR и о том, кто мержит в main
- [ ] Зафиксировать стек фронтенда: React + TypeScript + Vite, графики на Recharts или ECharts

### Дни 2–4: шаблон проекта

```
forecast-template/
├── frontend/   # дашборд
├── api/        # ASP.NET Core (C#)
├── ml/         # ноутбуки, train.py, predict.py, FastAPI-сервис
├── infra/      # docker-compose, .gitlab-ci.yml, скрипты деплоя
├── docs/       # презентация, схема архитектуры
└── Makefile    # make setup / train / up / deploy
```

- [ ] Каждый собирает свою часть по таблице ролей
- [ ] Зафиксировать контракты в OpenAPI: фронт ↔ C# API и C# API ↔ ML-сервис (входной ряд, горизонт, ответ с интервалами)
- [ ] Сквозной прогон «пустышки»: фронт → API → ML → ответ на графике

### Дни 5–6: генеральная репетиция

- [ ] Мини-хакатон на 4–6 часов на открытой задаче прогнозирования (Kaggle: продажи, энергопотребление, такси)
- [ ] Полный цикл: чистая VM → клонирование → обучение → деплой → защита за 5 минут
- [ ] Засечь, где теряется время, и исправить шаблон
- [ ] Отдельно проверить стык C# ↔ Python
- [ ] Подготовить запас на случай закрытых репозиториев: выгруженные образы, wheel-файлы, NuGet-пакеты

### День 7: финал

- [ ] Зафиксировать версии зависимостей
- [ ] Собрать доступы, ссылки и шпаргалки по командам в одном месте

## План на 2 дня хакатона

К концу первого дня в облаке должна работать полная версия на бейзлайне. Второй день уходит на улучшения, а не на спасение проекта.

| Когда | Капитан | ML | C#-бэкенд | Фронтенд | DevOps |
| --- | --- | --- | --- | --- | --- |

| День 1, 1–3 ч | Раздаёт задачи, следит за временем | EDA и бейзлайн | Загрузка данных, вызов ML-сервиса | Экраны под реальные данные | Первый деплой «пустышки» |
| День 1, 3–8 ч | Начинает презентацию | Признаки и модель | БД, история прогнозов | График прогноза | Стабилизация пайплайна |
| Конец дня 1 | Проверяет сквозной сценарий | Бейзлайн в проде | Сценарий работает | Сценарий работает | Рабочая версия задеплоена |

## Структура защиты

Защита идёт 5–7 минут, точное время уточнить у организаторов. Живое демо страхуется заранее записанным видео.

1. Задача и бизнес-ценность: кому и зачем нужен этот прогноз
2. Данные и ключевые инсайты EDA (1–2 графика)
3. Подход: бейзлайн → итоговая модель, валидация, метрика, прирост к бейзлайну
4. Живое демо задеплоенного сервиса
5. Архитектура и деплой: C# API, ML-сервис, контейнеры, CI/CD, облако
6. Ограничения и что сделали бы дальше

## Риски и меры

Главный риск — стык C# и Python, поэтому его проверяем отдельно на репетиции.

| Риск | Мера | Кто |
| --- | --- | --- |
| Окружение долго разворачивается на «голых» машинах | Скрипт установки, проверка на чистой VM | DevOps |
| C# API и ML-сервис не стыкуются | Контракт в OpenAPI, сквозной тест на репетиции | C#-бэкенд, ML |
| Утечка будущего в признаках или валидации | Валидация только по времени, ревью признаков | ML |
| Фронт и API не стыкуются | Контракт фиксируется в первый час | Фронтенд, C#-бэкенд |
| Деплой падает в последний момент | Деплой с первого дня, код-фриз за 3–4 ч | DevOps, капитан |
| Закрыты Docker Hub, PyPI или NuGet | Заранее выгруженные образы и пакеты, зеркала | DevOps |
| Демо падает на защите | Записанное видео демо | Фронтенд |
| Капитан уходит в код | Код только при закрытых задачах капитана | Капитан |
